# Corptie 分离浮球内容感知避让设计

## 1. 文档结论

Corptie 可以在 macOS 14 及以上实现“分离浮球自动避开重要屏幕内容”，但不应把“全白或全黑”直接等同于安全区域。

推荐方案是：

1. 用户主动开启“智能避让”，Corptie 才申请屏幕录制权限；
2. 使用 ScreenCaptureKit 对浮球附近做低频、局部截图；
3. 捕获时排除 Corptie 自己的全部窗口；
4. 用边缘密度、亮度方差、颜色复杂度、区域差异和帧间变化评估内容风险；
5. 在更大的搜索范围内先寻找风险最低的一组候选，再优先选择远离用户原始落点的位置；
6. 每个全局批次一次性计算全部有效浮球，统一提交所有满足改善条件的移动；
7. 用户正在悬停、拖动、回复或主动指定位置时绝不自动移动；
8. 截图只在本机内存中分析，不保存、不记录、不上传；
9. 权限缺失、捕获失败、受保护内容或没有更好位置时保持现状。

第一版不使用 OCR、神经网络或持续高帧率录屏。复杂视觉模型只有在简单评分无法可靠保护低对比度文字时才考虑。

## 2. 用户问题

分离浮球是一个始终置顶的 72 点圆形内容入口，外层窗口尺寸为 88×88 点。它的价值是让正在运行或等待用户处理的会话保持可见，但也可能遮挡：

- 编辑器中的代码和光标；
- 浏览器按钮、链接或正文；
- 表格中的数值；
- 终端输出；
- 视频、图像或图表；
- 其他应用中的通知和状态信息。

用户可以手动拖走浮球，但这会造成持续的注意力和操作负担。智能避让的目标不是保证“绝不覆盖任何像素”，而是在尊重用户位置意图的前提下，降低覆盖重要内容的概率。

## 3. 产品目标与非目标

### 3.1 目标

- 浮球优先停留在附近的低信息密度区域；
- 自动移动距离尽量短；
- 不产生持续跳动、追逐或突然跨屏；
- 多个浮球之间不重叠、不互相驱赶；
- 用户手动位置拥有更高优先级；
- 不影响单击、双击、拖动和快捷回复；
- 权限和本地处理方式对用户透明；
- 对 CPU、GPU、WindowServer 和电量影响可控；
- 在未授权或异常情况下安全降级。

### 3.2 非目标

第一版不尝试：

- 语义理解整个屏幕；
- 判断用户此刻正在阅读哪一行文字；
- 识别人脸、物体或应用业务语义；
- 自动跨显示器移动；
- 自动覆盖任意应用的空闲控件区域；
- 保存截图供历史分析；
- 将截图发送给后端、模型或第三方服务；
- 对快捷回复卡片做连续自动移动；
- 保证 DRM、受保护窗口和特殊合成表面的像素可见。

## 4. 为什么不能只检测全白或全黑

“全白或全黑”可以作为低风险信号，但不能作为唯一规则：

- 白色文档可能包含低对比度文字；
- 深色编辑器背景接近黑色，但可能正好覆盖代码；
- 视频暗场或黑边不一定是不重要内容；
- DRM 或受保护窗口可能在捕获结果中显示为黑色；
- 单色桌面壁纸可能是蓝色、灰色或其他颜色，但仍然安全；
- 毛玻璃、渐变和阴影可能颜色不纯，却没有实际内容。

更稳妥的定义是“低信息密度区域”：

- 局部颜色变化小；
- 边缘少；
- 明暗变化小；
- 相邻小块差异小；
- 短时间内变化少；
- 没有被识别为捕获异常；
- 不与其他浮球、屏幕边界和系统保留区域冲突。

接近纯白或纯黑只作为候选位置之间的次级加分项。

## 5. macOS 能力与权限

### 5.1 技术选择

Corptie 最低支持 macOS 14，可以使用：

- `SCShareableContent`：获取显示器、应用和窗口；
- `SCContentFilter`：捕获显示器并排除 Corptie；
- `SCStreamConfiguration.sourceRect`：只采样局部区域；
- `SCScreenshotManager.captureImage`：按需获取单帧；
- `CGPreflightScreenCaptureAccess()`：只读检查权限；
- `CGRequestScreenCaptureAccess()`：在用户主动操作后请求权限；
- `NSScreen.visibleFrame`：限制候选位置；
- `NSWorkspace.didActivateApplicationNotification`：前台应用变化时触发复检；
- `NSApplication.didChangeScreenParametersNotification`：显示器变化时重建上下文。

不使用已进入淘汰路径的 `CGWindowListCreateImage` 作为主实现。

### 5.2 权限边界

权限取决于是否读取其他应用或显示器的像素，与截图面积无关。即使只读取 72×72 点，也需要屏幕录制权限。

权限流程必须满足：

1. 功能默认关闭；
2. 设置页先解释用途和本地处理承诺；
3. 用户点击“启用智能避让”后才请求权限；
4. 不因创建浮球、应用启动或后台轮询自动弹出系统授权；
5. 用户拒绝后保持普通浮球行为；
6. 设置页提供打开系统“隐私与安全性 → 屏幕录制”的入口；
7. 权限被撤销时停止所有捕获并释放缓存；
8. 开发版和正式版都要验证 TCC 身份稳定性。

### 5.3 隐私约束

屏幕像素属于高敏感数据。实现必须保证：

- 图像不写入磁盘；
- 图像不进入日志；
- 图像不进入崩溃报告附件；
- 图像不进入后端 API；
- 图像不进入模型上下文；
- 图像不进入遥测；
- 只保留降采样后的短生命周期缓冲区；
- 下一帧到达或评分完成后释放上一帧；
- 日志只记录数值评分、候选坐标、耗时和错误类别；
- 设置文案明确说明“仅在本机内存中分析浮球附近区域”。

## 6. 社区与研究参考

### 6.1 Tamayura

Tamayura 的 `ObstructionOpacityController` 是最接近的社区实现：

- 每秒采样一次；
- 使用 64×64 图像；
- 排除自身应用；
- 计算颜色数量、亮度方差、边缘量和区域差异；
- 对评分做时间平滑；
- 根据复杂度改变悬浮层透明度。

Corptie 可以借鉴其架构和低成本特征组合，但不能直接复制代码。该仓库当前没有声明许可证。

### 6.2 macshot

macshot 的 ScreenCaptureKit 实现对 `SCShareableContent` 做短期缓存，原因是重复枚举可捕获内容会增加延迟。Corptie 也应使用共享捕获协调器，而不是让每个浮球单独枚举。

### 6.3 SmartOverlays

SmartOverlays 将覆盖物位置建模为以下成本的组合：

- 遮挡视觉显著区域的成本；
- 覆盖物与目标位置之间的距离；
- 连续帧之间的位置变化。

Corptie 不需要其 YOLO 和神经显著性模型，但应保留“内容风险 + 移动距离 + 时间稳定性”的优化结构。

### 6.4 UI 显著性研究

UEyes 等研究表明，软件界面的注意力分布与自然图像不同。通用自然图像显著性模型不一定适合桌面 UI，因此第一版优先使用可解释、可测试的图像统计特征。

## 7. 总体架构

建议新增四个职责清晰的组件：

~~~text
DetachedSessionManager
        │
        ├── DetachedSessionWindowController
        │       │
        │       └── DetachedOrbAvoidanceController
        │               │
        │               ├── ScreenContentSampler
        │               ├── OrbContentRiskAnalyzer
        │               └── OrbPlacementPlanner
        │
        └── DetachedOrbOccupancyRegistry
~~~

### 7.1 ScreenContentSampler

职责：

- 管理权限状态；
- 缓存 `SCShareableContent`；
- 按显示器建立捕获过滤器；
- 排除 Corptie 当前进程拥有的所有窗口；
- 将 AppKit 坐标转换成 ScreenCaptureKit 源区域坐标；
- 对搜索区域截图并降采样；
- 对并发截图做合并和限流；
- 捕获失败时返回结构化错误；
- 不负责决定浮球位置。

推荐以 `actor` 实现，避免多个浮球同时修改捕获状态。

### 7.2 OrbContentRiskAnalyzer

职责：

- 接收像素缓冲和候选圆形遮罩；
- 输出各项特征和总风险；
- 识别全黑异常、尺寸异常和空图像；
- 保持纯函数结构，便于用固定图像测试；
- 不访问 AppKit 和 ScreenCaptureKit。

### 7.3 OrbPlacementPlanner

职责：

- 生成候选位置；
- 过滤越界和重叠候选；
- 综合内容风险、移动距离和时间稳定性；
- 决定保持原位或移动；
- 输出理由和评分，不直接移动窗口；
- 保持纯函数结构，便于几何测试。

### 7.4 DetachedOrbAvoidanceController

职责：

- 监听浮球生命周期和交互状态；
- 安排采样；
- 维护锚点、冷却、迟滞和取消令牌；
- 调用分析器和规划器；
- 在主线程平滑移动窗口；
- 处理用户拖动、快捷回复和窗口关闭；
- 不持有原始截图超过一次评估周期。

### 7.5 DetachedOrbOccupancyRegistry

职责：

- 提供当前显示器上的其他浮球占用区域；
- 标记正在手动拖动或临时固定的浮球；
- 多浮球规划时提供稳定顺序；
- 防止多个控制器同时选择同一位置。

现有 `DetachedSessionManager.controllers` 已掌握所有浮球，可以直接扩展，不一定需要新类型。

## 8. 捕获流程

### 8.1 创建捕获上下文

首次启用或缓存失效时：

1. 调用 `SCShareableContent.excludingDesktopWindows(false, onScreenWindowsOnly: true)`；
2. 通过 `SCRunningApplication.processID` 或稳定 bundle identifier 找到 Corptie 进程；
3. 通过 `NSScreenNumber` 与 `SCDisplay.displayID` 配对显示器；
4. 为每个显示器创建排除 Corptie 应用的 `SCContentFilter`；
5. 缓存内容列表和过滤器；
6. 应用切换不必重建过滤器；
7. 显示器配置变化、捕获错误或缓存到期时重建。

不要把 `NSWindow.windowNumber` 直接假设成稳定的全局 WindowServer ID。排除整个 Corptie 进程更稳妥，也会自动排除浮球、快捷回复卡片和主窗口。

### 8.2 搜索区域

初始建议：

- 浮球窗口：88×88 点；
- 实际内容遮罩：72 点圆形；
- 搜索半径：360 点；
- 搜索区域：最大约 808×808 点；
- 单浮球截图输出：最长边 384 像素；
- 同显示器联合截图：按局部采样密度动态提高，最长边不超过 1024 像素；
- 光标：不捕获；
- 音频：不捕获；
- HDR：统一转换到 SDR 分析空间。

搜索区域必须与目标显示器的 frame 相交，并正确处理：

- Retina 缩放；
- 非 Retina 外接屏；
- 显示器负坐标；
- 显示器上下排列；
- 菜单栏和 Dock；
- 浮球跨越两块显示器边缘；
- 显示器热插拔。

### 8.3 多浮球捕获

第一版可以每个显示器每轮只截一次：

1. 收集该显示器上所有待评估浮球的搜索区域；
2. 计算这些区域的最小联合矩形；
3. 如果联合矩形没有大到接近整屏，执行一次截图；
4. 各浮球从同一图像中读取自己的区域；
5. 联合截图按原局部截图的采样密度动态计算输出尺寸，并限制最长边为 1024 像素；
6. 同一显示器同一轮只执行一个捕获任务，不同显示器之间仍由截图串行门保护。

如果实践中联合区域过大或性能不稳定，再比较“每浮球局部截图”和“每显示器 1 FPS 低分辨率 SCStream”，不在第一版直接引入常驻流。

## 9. 内容风险模型

### 9.1 输入

对每个候选位置，只分析实际被浮球可见内容覆盖的圆形区域。透明 halo 区域不计入主要遮挡，但可以额外采样一圈上下文，避免把浮球放在文字边缘。

每个候选位置输出：

~~~text
OrbContentRisk {
  edgeDensity
  localContrastSalience
  luminanceVariance
  colorEntropy
  regionalDifference
  temporalChange
  extremeToneBonus
  captureConfidence
  totalRisk
}
~~~

所有分量标准化到 `0...1`：

- 0 表示低风险；
- 1 表示高风险；
- `captureConfidence` 低时不允许自动移动。

### 9.2 边缘密度

目的：识别文字、图标、控件边缘和图表。

第一版可使用低成本梯度：

~~~text
gx = abs(L[x+1, y] - L[x, y])
gy = abs(L[x, y+1] - L[x, y])
edge = max(gx, gy)
~~~

统计超过阈值的像素比例，并结合平均梯度。无需第一版引入完整 Canny。

### 9.3 亮度方差

目的：区分纯色空白与明暗复杂内容。

采用感知亮度：

~~~text
L = 0.2126R + 0.7152G + 0.0722B
~~~

计算均值和标准差。方差低通常意味着纯色或缓慢渐变。

### 9.4 颜色复杂度

目的：识别照片、彩色图表和复杂界面。

可以将 RGB 各压缩到 3 位，统计颜色桶分布和归一化熵。仅统计颜色种类会对抗锯齿和压缩噪声过度敏感，熵更稳定。

### 9.5 区域差异

将候选区域分成 4×4 或 8×8 小块，计算相邻块平均亮度和颜色差异。它可以识别“左半边是空白、右半边有文字”的边界情况。

### 9.6 帧间变化

保留上一轮降采样的灰度特征，而不是完整图像。计算同一候选区域的平均绝对差：

~~~text
temporalChange = mean(abs(currentLuma - previousLuma))
~~~

动态视频、动画、进度条和滚动区域因此会获得更高风险。

### 9.7 纯白与纯黑加分

当以下条件同时成立时，给予小幅安全加分：

- 亮度均值接近 0 或 1；
- 方差低；
- 边缘密度低；
- 颜色熵低；
- 捕获没有被判断为异常。

纯白或纯黑不能覆盖其他高风险特征，也不能单独触发移动。

### 9.8 初始总风险

初始权重仅作为原型起点：

~~~text
contentRisk =
    0.30 * edgeDensity
  + 0.25 * localContrastSalience
  + 0.15 * luminanceVariance
  + 0.10 * colorEntropy
  + 0.10 * regionalDifference
  + 0.10 * temporalChange
  - 0.05 * extremeToneBonus
~~~

权重必须通过固定测试图和真实桌面观察模式校准，不能把上述数值视为最终产品参数。

## 10. 捕获异常与受保护内容

以下情况视为“未知”，而不是安全：

- 截图 API 返回错误；
- 输出为空或尺寸异常；
- 搜索区域整片为严格零值；
- 大范围显示器内容突然全部变黑；
- 权限在运行期间被撤销；
- 找不到对应显示器或进程过滤器；
- HDR/颜色转换失败；
- 屏幕锁定、快速用户切换或空间切换期间；
- 窗口处于不可共享或受保护状态。

当 `captureConfidence` 低时：

- 不自动移动；
- 不连续重试造成高负载；
- 使用指数退避；
- 设置页显示可诊断但不暴露屏幕内容的错误；
- 保留普通浮球行为。

## 11. 候选位置生成

### 11.1 搜索中心

持久 `userAnchor` 逻辑暂时停用。每个批次直接以浮球当前坐标作为搜索中心，自动换位后
下一批也从新位置重新搜索。手动拖动只改变浮球当前坐标，不再保存一个长期约束后续规划
的用户锚点。

### 11.2 搜索策略

使用覆盖近处和远处的离散候选：

- 当前点；
- 96、192、288、360 点半径；
- 每圈按 8 个方向采样；
- 无论距离多远，右、上、左、下每条边都加入 6 个均匀槽位，并额外保留与当前位置
  同轴的边缘候选；某个槽位被其他浮球占用时继续尝试同一条边的其他槽位；
- 对候选坐标做像素对齐；
- 去除重复位置。

候选生成仍按距离排序以保持结果确定性，但最终选择不再优先最小移动距离。

### 11.3 硬约束

候选位置必须：

- 完整位于 `visibleFrame`；
- 不进入菜单栏和 Dock；
- 不与其他浮球窗口相交；
- 不与当前展开的快捷回复卡片相交；
- 不跨显示器；
- 不处于用户明确禁用的边缘。

### 11.4 软成本

~~~text
placementCost =
    contentRisk
  - searchSeparationWeight * normalizedSearchSeparation
  + stabilityPenalty
  + edgePreferencePenalty
  + recentPositionPenalty
~~~

其中：

- `normalizedSearchSeparation` 鼓励离开本轮被判定为有内容的当前位置；
- `stabilityPenalty` 防止每帧改变位置；
- `edgePreferencePenalty` 倾向屏幕边缘；同属边缘安全候选时，方向优先级固定为
  右侧、上侧、左侧、下侧；
- `recentPositionPenalty` 防止在两个位置之间来回振荡。

### 11.5 决策规则

只有同时满足以下条件才移动：

1. 当前内容风险高于触发阈值；
2. 存在低于安全阈值的候选；
3. 候选风险相对当前至少改善一个显著幅度；
4. 当前不处于交互冻结状态；
5. 冷却时间已结束；
6. 捕获置信度足够高。

逐球二次确认会让不同浮球落入不同确认轮次，因此已移除。一个批次只有在所有已请求
浮球都生成有效当前位置分析时才允许提交；任意 evaluation 缺失会取消整个批次并在下一轮
重试。当前位置始终加入截图分析区域，即使它因与其他窗口相交而不能作为目标候选。

先过滤当前截图中不安全的候选，再保留与本轮最低风险相差不超过容差的候选。之后优先选择
距离屏幕边缘 24 点以内的位置，并按右、上、左、下排序。方向确定后，才在同一方向内部
比较历史安全区域的重叠次数和覆盖比例，最后比较当前风险。没有进入边缘带的候选时，也按
右、上、左、下选择方向。历史重叠次数不能把更高优先级的安全边缘提前淘汰；方向偏好也
不能覆盖明显更安全的位置。没有安全候选时保持原位。

### 11.6 时间安全区域

每轮分析完成后，只处理满足安全阈值的候选区域矩形，不保留截图、像素、文字或窗口
元数据。控制器持续维护一个最多 10 项的安全区域数组，每项包含矩形、重叠次数和最近
观测时间。

第一轮截图中的安全矩形以重叠次数 1 加入数组。以后每轮都将历史矩形与最新安全矩形
逐一求交；非空交集作为新的独立矩形保存，并把对应历史项的重叠次数加一。最新出现但
没有历史交集的安全矩形以次数 1 开始。旧矩形如果不再与当前安全区域相交，就不进入
下一轮数组。

~~~text
nextRegion = intersection(previousRegion, latestSafeRegion)
nextRegion.overlapCount = previousRegion.overlapCount + 1
~~~

完全相同的交集矩形会去重并保留更高次数；最终按重叠次数、矩形面积和输入顺序排序，
只保留前 10 项。候选与历史数组匹配时，先取重叠次数最高者，再比较该历史矩形覆盖
候选区域的比例。

规划顺序为：

1. 过滤当前帧不安全的候选；
2. 优先重叠次数最高的历史矩形；
3. 同次数下优先历史矩形覆盖比例更高的候选；
4. 再保留接近本轮最低风险的候选；
5. 最后选择离用户锚点更远的位置。

用户手动拖动、前台应用切换、Space 或屏幕配置变化、功能关闭或捕获暂停时清空历史，
防止把旧布局中的安全区域带入新场景。

### 12.1 禁止移动的状态

以下任一条件成立时取消待执行移动：

- 鼠标位于浮球或附件卡片上；
- 用户正在按下鼠标；
- 用户正在拖动；
- 单击刚触发快捷回复；
- 双击正在打开完整会话；
- 快捷回复输入框已聚焦；
- 审批、确认或选项卡片处于交互中；
- 附件窗口是 key window；浮球本身成为 key window 不能单独冻结避障，因为拖动或点击后
  它可能长期保持 key 状态；
- 窗口即将关闭；
- 当前正在切换屏幕或空间；
- 用户刚手动拖动；
- VoiceOver 或其他辅助交互正在操作该窗口时，若可检测。

跟踪事件可能因窗口移动、拖动结束于窗口外或系统事件切换而丢失。每次准备截图前，
控制器必须用 `NSEvent.pressedMouseButtons` 和当前全局鼠标坐标校正 `pointerDown` 与
`hover` 状态，避免某个浮球因残留交互标志永久停止分析。

### 12.2 用户拖动后的规则

- 拖动期间不捕获、不移动；
- mouse up 后保留已有亮度签名和历史安全区域；
- 清除自动移动的防回跳位置，避免用户手动决定被旧的移动轨迹约束；
- 等待约 600–900 毫秒再分析；
- 冷却结束后恢复普通候选规划，包括无距离限制的四边吸附候选。

### 12.3 自动移动

- 不展示跨越屏幕内容的直线路径。标准模式先在原位用 120 毫秒淡出并缩小到
  `0.78×`，完全隐藏后直接更新窗口坐标，再用 130 毫秒淡入并放大到 `1.04×`，
  最后用 50 毫秒回落到 `1×`，总时长 300 毫秒；
- 开启“减少动态效果”时不缩放，只执行 80 毫秒淡出、隐藏换位和 80 毫秒淡入；
- 同一批次的所有浮球必须同步进入消失、换位、出现三个阶段；
- 用户在消失阶段开始交互时取消换位并在原位置恢复；坐标已更新后开始交互时，
  在目标位置立即恢复；
- 动画期间不启动新评估；
- 更新附件卡片位置；
- 不激活 Corptie；
- 不改变 key window；
- 不抢键盘焦点；
- 不播放声音；
- 移动后进入至少 2–3 秒冷却；
- 记录数值诊断，不记录图像。

## 13. 触发与采样频率

优先使用事件触发，再用低频轮询补充。

### 13.1 状态失效

新浮球创建、用户拖动、前台应用或 Space 切换、屏幕配置变化、附件交互结束及功能
重新启用时，只负责清理已经失效的候选确认、亮度签名或安全区域历史。实际捕获和移动
仍进入下一次全局批次，避免不同浮球各自触发独立循环。

### 13.2 周期触发

所有浮球共享唯一调度器。活动状态下每 2 秒启动一个批次；连续 3 个完整批次中全部有效
浮球都处于安全状态后降到 5 秒。出现移动、仍有高风险位置或有球因交互被跳过时恢复 2 秒。
真实截图失败按 5、10、20 秒指数退避，成功后立即恢复正常节奏。批次开始时冻结本轮所有
浮球的初始位置；按显示器合并搜索区域并各执行一次截图后，再统一计算全部目标位置。
计算耗时从下一轮等待时间中扣除。没有浮球时停止调度，用户正在交互的单个浮球跳过本轮，
但不影响其他浮球。

## 14. 多显示器与多浮球

### 14.1 多显示器

- 每个浮球只在当前显示器内搜索；
- 自动移动不跨屏；
- 用户拖到另一显示器后重建捕获上下文；
- 使用 display ID，不依赖 `NSScreen.screens` 数组顺序；
- 分别处理 backing scale；
- 显示器断开时使用现有安全放置逻辑迁移窗口；
- 镜像显示器只对实际捕获 display 建立一次上下文。

### 14.2 多浮球

同一批次先完成所有浮球的捕获和风险分析，再按当前风险从高到低规划。已分配的目标
矩形作为后续浮球的额外占用区域，防止两个球得到相互重叠的目标。所有目标都确定后，
统一进入同一套 300 毫秒换位时序：原位同步消失、隐藏状态下逐个更新已规划坐标，
再在目标位置同步出现。屏幕上不会展示浮球穿过中间内容的轨迹。

如果多个浮球都需要避让：

- 本轮先计算所有不冲突的目标；
- 所有已接受目标在同一个动画组中一起移动；
- 不允许互相交换位置；
- 不允许形成追逐循环；
- 候选位置历史用于检测 A/B 振荡。

## 15. 快捷回复附件

第一版只自动移动浮球，不在附件卡片展开时移动。

现有附件控制器已经根据屏幕边界在左、右、上、下之间选择位置。后续可以将四个方向作为候选，并复用内容评分：

~~~text
accessoryPlacementCost =
    coveredContentRisk
  + outOfBoundsPenalty
  + overlapPenalty
  + directionChangePenalty
~~~

附件是用户主动打开的短期界面，因此：

- 不需要持续追踪背景；
- 只在展开前截取一次；
- 优先保证可操作性和不越界；
- 内容风险只是方向选择因素；
- 不能为了避让而移动浮球本身。

## 18. 性能预算

原型阶段需要用 Instruments 测量，而不是只看功能正确：

- 无浮球时：零捕获、零定时任务；
- 功能关闭时：零 ScreenCaptureKit 调用；
- 用户交互时：停止捕获；
- 同一显示器：同一时间最多一个截图；
- 默认不超过每显示器每秒一次；
- 输出分辨率远低于原生屏幕分辨率；
- 图像处理在后台执行；
- AppKit 窗口更新只在主线程执行；
- 不保留完整分辨率图像；
- 捕获枚举使用短期缓存；
- 应用进入退出、睡眠和锁屏时停止调度。

建议验收目标：

- 静态桌面平均 CPU 增量接近不可感知；
- 单次分析不阻塞主线程；
- 拖动和点击不掉帧；
- 内存不会随检测次数增长；
- WindowServer 占用没有持续异常增长；
- 电池模式下可降低采样频率。

## 19. 可观测性

开发构建可输出：

~~~text
[orb-avoidance] permission=granted
[orb-avoidance] capture display=1 rect=... duration_ms=...
[orb-avoidance] current_risk=0.73 best_risk=0.18 distance=64
[orb-avoidance] decision=hold reason=hysteresis
~~~

禁止输出：

- base64 图像；
- OCR 文字；
- 前台窗口标题；
- 文件名、URL 或文档内容；
- 可还原屏幕内容的高维特征。

正式构建默认关闭详细评分日志，只保留错误类别和性能计数。

- 风险近似时优先选择离文字区域更远的安全候选；

- 不越界、不跨屏、不重叠；
- 不在两个位置间振荡；
- 自动结果不覆盖用户锚点；
- 规划器是无窗口副作用的纯逻辑；
- 测试、重建、App 和后端验证通过。

### Step 5：浮球控制器集成

验收：

- 悬停、拖动、回复和菜单期间不移动；
- 自动移动不激活应用、不抢焦点；
- 多浮球不会重叠或追逐；
- 关闭浮球后没有后台孤儿任务；
- 权限或捕获失败时保持原位；
- 测试、重建、App 和后端验证通过。

生产路径不会把 `CGImage` 或 RGBA 数组传给窗口控制器。完整截图仅在
`ScreenContentSampler` actor 内短暂存在；控制器接收归一化风险值和内存中的灰度签名。
代码不保存截图、不执行 OCR、不上传像素，也不记录窗口标题、文件名、URL 或屏幕文本。

### 26.2 当前参数

| 参数 | 实现值 |
|---|---:|
| 最长采样边 | 单球 384 px；同显示器联合截图动态提高，封顶 1024 px |
| 搜索半径 | 96、192、288、360 pt |
| 每圈方向 | 8 |
| 风险触发阈值 | 0.26 |
| 安全候选阈值 | 0.18 |
| 最小风险改善 | 0.08 |
| 批次提交 | 单轮直接提交；任一已请求浮球 evaluation 无效则整批取消 |
| 自动移动 | 标准模式 120 ms 消失 + 130 ms 出现 + 50 ms 回落；减少动态效果时 80 + 80 ms 纯淡入淡出 |
| 移动冷却 | 2.5 s |
| 全局批次 | 活动期 2 s；连续 3 个安全批次后 5 s；一轮计算全部目标后同时移动 |
| 捕获失败 | 整个批次保持原位，按 5、10、20 s 退避 |
| 防回跳历史 | 最近 4 个位置，15 s 内有效 |
| 安全区域历史 | 最多 10 个交集矩形，记录重叠次数，最长 30 s |
| 可捕获内容缓存 | 2 s |

同一显示器上的所有浮球在每轮共享一张联合截图，截图请求再由 `AsyncSerialGate`
串行化。即使 Swift actor 在等待 ScreenCaptureKit 时发生可重入，不同显示器也不会同时
执行截图。联合截图只构建一次亮度特征帧，所有候选遮罩共享该帧。

### 26.4 回滚

用户关闭“智能浮球避让”后，偏好发布立即取消所有待处理观察任务并清理采样缓存。
权限被撤销、系统锁屏/睡眠、截图失败或分析结果 unknown 时均保持原位。
普通浮球、拖动、单击、双击和附件卡片不依赖屏幕捕获，可继续使用。

### 26.5 已知限制和人工门禁

以下项目不能由默认关闭的自动化运行替代，必须由用户在设置中主动启用功能并授予
macOS“屏幕录制”权限后执行：

- Finder、浏览器、编辑器、终端、表格、图片、视频和受保护内容的阈值观察；
- 双显示器不同缩放、上下排列、Stage Manager、Mission Control 和 Space 的真实捕获；
- 睡眠唤醒、外接屏热插拔、VoiceOver、减少动态效果和长时间运行；
- 使用 Instruments 验证真实 ScreenCaptureKit 负载、WindowServer、能耗和长期内存曲线。

本次自动化开发没有代替用户触发权限请求，因此不能声称上述真实桌面矩阵已经通过。
在这些人工项目完成前，本功能应保持“默认关闭、用户可选”，不应作为默认启用能力发布。

当前 Development 可执行文件是 SwiftPM 生成的 ad-hoc 签名，designated requirement 为
CDHash；重新构建会改变 CDHash，因而屏幕录制授权可能需要重新确认。生产打包脚本现支持
通过 `CORPTIE_APP_SIGNING_IDENTITY` 指定固定 Developer ID Application 身份；未指定时仍
使用 ad-hoc 签名并输出警告。正式发布前必须使用真实签名身份，并在实际安装/升级路径中验证
TCC 权限保留或清晰的重新授权流程。本次开发没有可用的 Developer ID，因此未执行该人工门禁。

当前没有引入 Metal。ScreenCaptureKit 负责系统截图，截图后的 RGBA 转换、共享亮度特征、
圆形遮罩统计和规划仍在 CPU 上执行。稀疏候选与共享特征后的自动化压力结果尚未显示出
引入 GPU 管线的必要性；若 Instruments 的真实桌面测试仍显示图像分析是主要瓶颈，应先
比较 Accelerate/vImage，只有在更高采样频率或更大联合帧下仍不达标时再实现 Metal 特征图。
